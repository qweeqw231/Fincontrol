## 0. 验收原则

1. 先验收需求/验收文档，再启动代码补救。
2. 自动化测试通过只是必要条件；数据 Oracle 与浏览器视觉验收同样必须通过。
3. 不以“页面显示了数字”为通过标准，必须验证数字来源、日期和分母。
4. 不允许用 0 代替 unknown，不允许用当前配置伪造历史配置。
5. 累计/持有收益成熟逻辑采用**零业务语义变更**回归：四个值、算法、快照、基金数、Info 说明与余额宝 fallback 均须保留。
6. Phase 2/3/5 页面本轮只验收说明书完整性，不做运行时通过声明。

## 7. 累计 / 持有收益成熟逻辑保护验收

本节为硬门禁；任何一项失败都不得以“视觉已完成”验收。

### 7.1 数据语义不变

| 展示格 | API 字段 | 现行语义 |
|---|---|---|
| 累计收益率 | `returnRate` | `Σ cumulativeProfit / Σ amount`，现行口径 |
| 持有收益率 | `holdingReturnRate` | `Σ holdingProfit（含现行余额宝调整）/ Σ amount` |
| 累计收益额 | `totalCumulativeProfit` | 当前口径累计收益合计 |
| 持有收益额 | `totalHoldingProfit` | 当前口径持有收益合计 |

- [ ] 前端四值与 API 原值一致，只做格式化；
- [ ] `phase1_simple` 标识保留；
- [ ] `snapshotDate` 和 `fundCount` 保留；
- [ ] `rawHoldingProfit`、`balanceFundAdjustment`、`balanceFundStatus` 现行处理不变；
- [ ] status=normal/included/excluded_unknown 的 Info 文案分支不变；
- [ ] 四个 Info 入口均可打开和关闭；
- [ ] 正红、负绿、零灰仅是视觉变化，不改变正负号；
- [ ] 旧的 AssetQueryServiceTest 和 CumulativeReturnCard 相关 fixture 全部通过。

### 7.2 布局

桌面端必须可读为以下 2×2 矩阵，而非四段无标注数字：

|  | 累计 | 持有 |
|---|---|---|
| 收益率 | 值 + Info | 值 + Info |
| 收益额 | 值 + Info | 值 + Info |

窄屏可改为两列缩放或两组纵向排列，但四个语义标签不得消失。
