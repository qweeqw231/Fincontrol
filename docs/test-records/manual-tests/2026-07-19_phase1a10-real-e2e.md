### 9.1 余额宝 holding=NULL 被 0 覆盖（**✅ 已修复 2026-07-19 15:46**）

- **现象（修复前）**：DB 写库 `holding_profit=0.00, profit=0.00`，与 ground truth holding=NULL 不一致。
- **根因**：
  - `VisionModelClient` 解析出的 `holdingProfit=0, profit=0`（模型将余额宝“缺列”补 0）
  - `SnapShotConfirmService` `BigDecimal holding = fund.getHoldingProfit() != null ? … : (fund.getProfit() != null ? fund.getProfit() : BigDecimal.ZERO)` 一直 fallback 到 0
- **修复（方案 A：Service 层余额类特例）**：
  - `SnapShotConfirmService.writeAssetRaw` 第 182-202 行加余额类判断：
    ```java
    boolean isBalanceCategory = "余额类".equals(cat.getCategoryName());
    if (isBalanceCategory) {
        holding = null; profit = null;
        cumulative = fund.getCumulativeProfit();
    } else { /* 原 fallback 逻辑 */ }
    ```
  - `schema-h2.sql` 与 `MySQL 1a10-migration.sql`：`profit` 列同步允许 NULL（与 holding_profit 语义一致）
- **验证（2026-07-19 15:46 重跑）**：
