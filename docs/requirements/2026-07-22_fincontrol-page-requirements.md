## 0. 文档效力、目标与保护边界

### 0.1 文档目标

本文是 FinControl 页面展示、交互、数据口径和验收语义的统一需求基线，用于解决“已有 API 和组件存在，但页面应展示什么、如何计算、如何验收没有统一说明”的问题。

### 0.2 文档优先级

发生冲突时，按以下顺序执行：

1. 已冻结的最新业务决策及本文冻结版；
2. 专项决策文档（如决策 27、累计/持有收益现行标准）；
3. API 契约；
4. Phase 工作计划与验收计划；
5. 历史评审记录、示例 HTML 和旧验收文字。

### 0.3 成熟业务逻辑保护原则（强制）

- 当前已经通过验收的解析、去重、确认入库、快照切换、累计/持有收益、余额宝 fallback、AI 路由与缓存等成熟逻辑，**不得因前端美化而重写或改变语义**。
- 本轮补救只允许：
  1. 修复重大数据加载/绑定 Bug（如解析历史基金数为 0、分类计数为 0、当前快照跨日期串数、比例未加载）；
  2. 补足缺失的查询与展示映射；
  3. 调整前端信息架构、样式和可访问性；
  4. 为修复新增回归测试。
- 若修复必须触碰成熟业务服务，需先证明根因、增加保护性测试，并采用最小差异修改。
- 不以本需求说明书为理由提前实现 Phase 2/3/5 页面；这些页面在本文中先冻结目标契约和交互。

## 1. 全局数据口径宪法

所有页面必须遵循以下定义。页面、表头、Tooltip 和接口说明中禁止单独使用含糊的“占比”一词。

### 1.1 变量与公式

| 变量名 | 定义 | 计算公式 / 来源 |
|---|---|---|
| `V_all` | 总资产（含余额类） | `sixCategoriesTotal + balanceFund` |
| `V_6` | 六大类总值（不含余额类） | `sixCategoriesTotal` |
| `V_balance` | 余额类金额 | `balanceFund` |
| `V_category` | 某大类金额 | `categoryTotal` |
| `V_fund` | 单只基金金额 | `fund.amount` |
| `R_fund_in_category` | 基金类内占比 | `V_fund / V_category × 100%` |
| `R_category_in_six` | 大类占六大类 | `V_category / V_6 × 100%` |
| `R_item_in_all` | 项目占总资产 | `V_item / V_all × 100%` |
| `targetRatio` | 目标比例 | 从 `user_config.target_ratios` 读取 |
| `deviation` | 配置偏差 | `R_category_in_six - targetRatio` |

### 1.2 强制规则

- **DATA-G-001**：“六大类”永远只指货币类、固收类、商品类、A股权益类、海外权益类、港股大中华类，不包含余额类。
- **DATA-G-002**：所有金额在后端使用 Decimal/BigDecimal；前端只负责格式化展示，不用浮点结果反写业务数据。
- **DATA-G-003**：百分比使用未取整金额计算，最终展示时才四舍五入；禁止用已显示的百分比二次计算。
- **DATA-G-004**：目标比例以 `user_config` 为权威源；修改配置不回写或篡改历史快照。
- **DATA-G-005**：`holdingProfit`（持有收益）与 `cumulativeProfit`（累计收益）严格区分，禁止互相冒充。余额宝 fallback 和缺失值处理沿用现行成熟标准。
- **DATA-G-006**：列名必须写成“类内占比”“占六大类”或“占总资产”；禁止仅写“占比”。
- **DATA-G-007**：分组基金表若展示“类内占比”，同一大类基金之和及小计必须为 100%（允许显示舍入误差校正后的 100.00%）。
- **DATA-G-008**：大类配置表展示“占六大类”，六个大类之和及合计必须为 100%。
- **DATA-G-009**：余额类不参与“占六大类”和目标偏差，显示 `—（不参与配置）`；如单独展示“占总资产”，使用 `V_balance / V_all`。
- **DATA-G-010**：首页所有资产金额、分类、基金数和收益模块必须原子性绑定同一个 `snapshot_meta.is_current` 对应 `snapshotDate`。
- **DATA-G-011**：数量必须明确口径。示例：六大类基金 18 只、余额类 1 只、总基金 19 只，禁止三个概念混用。
- **DATA-G-012**：`null`/缺失/未知值显示 `—`；已知数值零必须正常显示 `0.00` 或 `0.00%`，不得把零当作空值。计算分母为 0 且比例不可定义时显示 `—`。
- **DATA-G-013**：收益小计使用可用基金收益求和；正负收益恰好抵消为零时，小计必须显示 `0.00`，不能显示 `—`。只有参与求和的收益全部未知时，小计才显示 `—`。

### 1.3 小计语义

| 表格类型 | 明细行计算 | 小计 / 合计语义 |
|---|---|---|
| 某大类内部基金表 | `V_fund / V_category` | 该大类小计 = 100% |
| 六大类配置表 | `V_category / V_6` | 六类合计 = 100% |
| 基金占总资产表（仅在明确需要时） | `V_fund / V_all` | 大类小计 = `V_category / V_all`，全资产合计 = 100% |

不得在同一列混用上述分母。若页面需同时展示两种比例，必须拆为两个具名列。

### 1.4 金额、比例和时间格式

- 金额：人民币符号 + 千分位 + 2 位小数，如 `¥ 7,850.38`。
- 表格金额：表头写明“元”，单元格可省略 `¥`，但同表必须一致。
- 比例：默认 2 位小数；环形图标签可显示 1 位，Tooltip 显示 2 位。
- 正数在需要表达变化时加 `+`；普通金额不加 `+`。
- 快照日期：`YYYY-MM-DD`；操作时间：本地时区 `HH:mm:ss`；完整时间用于 Tooltip。
- 空值：`—`；不得将未知值显示为 0，也不得将已知数值 0 显示为 `—`。

## 2. 全局样式约束

### 2.1 配色方案

| 元素 | 颜色 | 色值 |
|---|---|---|
| 页面背景 | 浅灰 | `#F5F5F5` |
| 卡片背景 | 白色 | `#FFFFFF` |
| 主色（标题栏、主按钮） | 深蓝 | `#0A59F7` |
| 涨 / 正收益 / 超配 | 红色 | `#FF4D4F` |
| 跌 / 负收益 / 低配 | 绿色 | `#52C41A` |
| 中性 / 零 / 次要文字 | 灰色 | `#8C8C8C` |
| 警告 / 待确认背景 | 浅橙 | `#FFF3E0` |

> 中国市场业务涨跌色与通用 Web 成功/失败色必须使用不同 token 命名，例如 `--color-finance-up` 与 `--color-system-error`，避免语义串色。

### 2.2 间距、圆角和阴影

| 元素 | 属性 | 值 |
|---|---|---|
| 卡片 | 圆角 | `8px` |
| 卡片 | 阴影 | `0 2px 8px rgba(0,0,0,0.06)` |
| 卡片 | 内边距 | `20px 24px` |
| 卡片间距 | 外边距 / grid gap | `16px` |
| 按钮 | 圆角 | `4px` |

### 2.3 表格与图表

- 表头使用浅灰背景，字段名不换行；名称列左对齐，数字列右对齐。
- 金额、比例和收益使用 tabular numbers；正负收益使用业务涨跌色。
- 表格必须有清晰的行分隔、分组标题与小计背景，Hover 仅增强定位，不改变数据颜色。
- 窄屏允许表格横向滚动，不压缩到字段重叠。
- 六大类颜色在所有图表中保持固定，不因排序改变。
- 图表必须有文本/表格等价信息，不能仅靠颜色表达。

### 2.4 全局页面状态

每个读取型模块必须具备：

- Loading：骨架屏或明确的加载文案；
- Empty：说明为什么为空，并提供可执行入口；
- Error：保留页面框架，显示错误摘要和重试按钮；
- Stale：若展示缓存或非当前日期，必须显示日期标识；
- Disabled：未来阶段页面显示阶段和开放条件，不伪装可操作。

## 4. 首页 `/`

### 4.1 目标、阶段和数据源

- **页面目标**：用户打开系统后，一眼看清当前资产配置、收益与偏差，并快速进入核心操作。
- **启用阶段**：Phase 1b。
- **权威数据源**：
  - `GET /api/snapshot/latest?includeDetail=true`
  - `GET /api/asset/cumulative-return`
  - `GET /api/asset/operations/recent?limit=5`
  - 余额展示必须与当前快照一致；若继续调用 `/api/asset/balance`，该接口也必须绑定 `is_current` 日期。

### 4.2 展示顺序

#### HOME-001 品牌 Header

- 钱袋图标与 `FinControl` 必须同一行；不得上下断开。
- 品牌文字第二行显示“个人资产配置全景 · 支付宝快照”。
- 右侧显示当前 `snapshotDate` 和来源“支付宝”。

#### HOME-002 总资产 Hero

- 展示 `V_all`，格式如 `¥ 7,850.38`。
- 显示口径“总资产（含余额类）”和当前快照日期。
- 不伪造昨日变动；无历史对比数据时不显示涨跌。

#### HOME-003 数据卡片

桌面端三张卡片并排：

1. 六大类总值：`V_6`；
2. 余额类：`V_balance`，副标题“定投水源”；
3. 累计 / 持有收益卡：沿用现行成熟逻辑。

累计 / 持有收益卡采用 **2 行 × 2 列数据矩阵**：

|  | 累计 | 持有 |
|---|---|---|
| 收益率 | `returnRate` | `holdingReturnRate` |
| 收益额 | `totalCumulativeProfit` | `totalHoldingProfit` |

强制要求：

- 四个值均有明确“累计/持有 + 收益率/收益额”标注，不能只靠位置猜测。
- 四个值各自保留现行 Info 标注/弹窗，公式、定义、算法和余额宝 fallback 文案沿用现行标准。
- 保留 `algorithm`、`snapshotDate`、`fundCount` 注记。
- 保留现行 `phase1_simple` 与余额宝 `balanceFundStatus` 处理，不改变成熟计算逻辑。
- 正收益红、负收益绿、零灰；这是展示规则，不改后端数值。

#### HOME-004 中间双栏

左侧“六大类分布”环形图：

- 仅过滤后的六大类；余额类不得进入图表。
- 使用 `categoryTotal` 绘图；图表内部比例为 `R_category_in_six`，合计 100%。
- Tooltip 显示类别、金额、占六大类、目标、偏差。

右侧“配置偏差分析”表：

| 列 | 口径 |
|---|---|
| 大类 | canonical categoryName |
| 金额（元） | `V_category` |
| 占六大类 | `R_category_in_six` |
| 目标比例 | `targetRatio` |
| 偏差 | `deviation` |

表尾合计金额为 `V_6`，占六大类和目标均为 100%。

#### HOME-005 基金持仓明细

- 默认折叠，展开后按六大类分组；余额类不在该表展示。
- 列：基金名称、持仓金额（元）、持有收益（元）、累计收益（元）、类内占比。
- `R_fund_in_category = fund.amount / categoryTotal`。
- 每组小计金额等于该大类金额，类内占比固定显示 100.00%。
- 持有/累计收益的基金行若字段缺失显示 `—`；已知为零则显示 `0.00`。
- 小计收益按可用基金行加和。示例：`+3.84 + (-3.84) = 0.00`，港股大中华类小计的持有收益和累计收益均应显示 `0.00`，不能显示 `—`。
- 若该大类所有基金的某一收益字段均为缺失，才将对应收益小计显示 `—`。

#### HOME-006 口径说明与执行总结

- 口径说明明确余额类不参与六大类配置。
- 执行总结为只读文本区域，可由实际/目标/偏差动态生成，不允许写死具体日期和金额。

#### HOME-007 快捷入口

三张操作入口卡：

- 上传新快照 → `/data`
- 月度校正 → `/correction`（未启用时显示 Phase 2）
- 咨询 AI 顾问 → `/ai`

#### HOME-008 最近操作

- 最近 3–5 条，显示操作时间、类型、摘要和关联快照日期。
- 解析记录必须显示真实总基金数；有分类计数时显示类别摘要。
- 不得把无法解析的成功记录静默显示为“解析 0 只基金”。未知时显示“基金数未知”并标注数据异常。

### 4.3 页面状态

- Loading、Error、Empty 分模块展示；一个辅助接口失败不得清空已成功的总资产快照。
- 无快照时展示“先上传资产截图”并跳转 `/data`。
- 切换 `is_current` 后，所有 HOME 模块必须刷新并显示同一 `snapshotDate`。

## 5. 数据管理 `/data`

### 5.1 目标、阶段和数据源

- **页面目标**：上传支付宝截图，交由 AI 解析，核对分类和金额，确认入库并管理当前快照。
- **启用阶段**：Phase 1b。
- **现行数据源**：
  - 上传：`POST /api/screenshot/upload`
  - 单图解析：`POST /api/screenshot/parse`
  - 多图编排：`POST /api/screenshot/parse-batch?mode=single|multi`
  - 确认：`POST /api/snapshot/confirm`
  - 撤销：`DELETE /api/snapshot/confirm/{snapshotId}`
  - 设为当前：`POST /api/snapshot/set-current`
  - 快照列表：`GET /api/snapshot/meta-list`
  - 解析日志：`GET /api/parse-logs` 或现行最近操作接口。

### 5.2 状态机

`idle → selected → uploading → parsing → parsed → reviewing → confirming → confirmed → rollback-window → completed`

任一步可进入 `error`；用户修正后回到该步骤重试，不清空已成功步骤的数据。

### 5.3 页面模块与交互

#### DATA-001 上传区

- 当前支付宝连续持仓页流程要求 4 张图；显示已选数量 `n/4`、缩略图、文件名、删除和替换。
- 显示逐文件上传/解析状态，不只显示一个全局 Spinner。
- 未达到 4 张时禁用批量解析按钮，并说明原因。

#### DATA-002 解析设置

- 模式选择：single（逐图，推荐）/ multi（多图一次解析）。
- 快照日期可编辑；数据日期优先使用用户选择值覆盖 AI 识别值。
- 请求期间按钮禁用，防止重复提交。

#### DATA-003 解析结果和大类确认

- 展示每只基金：基金名称、金额、持有收益、累计收益、AI 类别、确认状态。
- 用户可修正类别、忽略单条、重新解析；成熟 category resolver 优先级不改变。
- 未确认/AI 猜测使用浅橙背景，已确认使用中性背景。

#### DATA-004 入库预览

概览卡：`V_all`、`V_6`、`V_balance`、总基金数、快照日期。

分类表：

| 列 | 要求 |
|---|---|
| 类别 | canonical name |
| 金额（元） | 分类基金金额合计 |
| 占六大类 | 六大类按 `R_category_in_six`；余额类显示 `—` |
| 基金数 | `category.funds.length`，不得读取不存在的 `fundCount` |

- 六大类行合计占六大类 100%；总基金数等于各类基金数之和。
- 基金明细表列出基金、类别、金额；必要时同时显示两种收益。
- 显示 DedupReport 的输入数、去重后数、丢弃数和警告。

#### DATA-005 二次确认与入库

- 二次确认明确目标日期、覆盖提示、分类金额和基金数。
- `confirm` 请求期间禁用所有重复提交入口。
- 成功后刷新快照列表与全局资产 store。
- 在后端支持且返回有效标识时显示 10 秒撤销；超时后入口消失，失败显示明确原因。

#### DATA-006 快照管理

- 列表显示快照日期、confirmedAt、is_latest、is_current。
- “设为当前”必须二次确认；成功后刷新首页相关 store。
- `is_latest` 与 `is_current` 的语义按决策 27，不在前端自行推断。

#### DATA-007 解析历史

- 每条显示创建时间、快照日期、状态、provider、fallback、总基金数和各大类基金数。
- 原始模型内容含 Markdown/代码块时，后端仍应提取结构化 JSON 计数。
- 解析失败显示失败状态和重试入口；成功但结构无法恢复时显示“计数未知”，禁止显示假 0。

### 5.4 页面状态

每个步骤有独立 Loading/Error；关闭确认弹窗不得丢失解析结果；确认成功后才清除上传草稿。

## 6. AI 顾问 `/ai`

### 6.1 目标、阶段和数据源

- **页面目标**：与 AI 多轮对话，基于当前资产快照获得配置分析和规则内建议。
- **启用阶段**：Phase 1b。
- **当前/目标数据源**：`POST /api/chat/send`、会话列表/详情/创建/删除接口。`GET /api/chat/{conversationId}/history` 作为目标语义，实际路径以 API 契约中的 conversations 接口为准，实施前统一命名。

### 6.2 页面模块

- **AI-001 对话列表**：左侧按最近更新时间排序；支持新建、切换、删除（删除二次确认）。
- **AI-002 消息区**：区分用户/助手气泡，显示时间、发送状态、失败重试；保留 Markdown 安全渲染边界。
- **AI-003 输入区**：多行文本、发送按钮、快捷提问“本月补仓建议”；空文本不可发送。
- **AI-004 路由标注**：可查看 `routedTo`、intent 或相关调试标识，但不干扰主要回答。
- **AI-005 上下文**：涉及资产问题时明确回答基于哪个 `snapshotDate`；无快照时提示先上传，不伪造数据。
- **AI-006 状态保持**：路由切换后当前 conversationId 和历史消息可恢复；请求中防重复发送。

流式与一次性响应均可，取决于后端能力；前端必须有统一等待态。

## 7. 月度操作台 `/correction`

### 7.1 目标、阶段和数据源

- **页面目标**：基于当前六大类配置和预算，计算本月货币类/固收类补仓及高波定投安排。
- **启用阶段**：Phase 2。
- **目标数据源**：`GET /api/correction/defaults`、`POST /api/correction/monthly/calculate`、recalculate、confirm。

### 7.2 页面模块与交互

- **CORR-001 默认值**：加载 `V_curr (= V_6)`、`V_m`、`V_b`、`V_high`、`U_high`、目标比例、预算和申购门槛；字段明确写“六大类总值（不含余额类）”。
- **CORR-002 输入表单**：允许调整业务允许的输入；展示来源快照日期；脏状态在离开页面时提示。
- **CORR-003 计算结果**：展示理论补仓、定投拆分、总投入、预算差额和约束警告，不在前端复制求解算法。
- **CORR-004 取整弹窗**：展示系统建议；用户修改实际值后调用后端实时重算新比例和偏差。
- **CORR-005 二次确认**：确认操作项、金额、来源快照、取整策略和警告后写入 `operation_log`。
- **CORR-006 审计结果**：成功显示 operationLogId 和确认时间；刷新首页最近操作，不修改资产快照金额。

无快照时提供跳转 `/data`，不显示全 0 的伪默认值。

## 8. 资产配置 `/config`

### 8.1 目标、阶段和数据源

- **页面目标**：设定六大类目标比例和预算约束。
- **启用阶段**：Phase 2。
- **数据源**：`GET /api/config`、`POST /api/config`。

### 8.2 页面模块与交互

- **CONF-001 目标比例**：六个 canonical 类别逐项输入；实时显示合计；保存时必须恰为 100%。
- **CONF-002 预算参数**：budgetLimit、purchaseThreshold、highVolDcaBudget 等字段显示单位、范围和说明。
- **CONF-003 校验**：非数字、负数、超范围、比例合计不为 100 时就地提示并禁用保存。
- **CONF-004 脏状态**：修改后显示“未保存”；离开页面提示；保存成功后更新 `userConfigStore`。
- **CONF-005 写入边界**：保存仅写 `user_config`，返回 `triggeredSnapshotUpdate=false`，不得回写历史 `asset_snapshot`。
- **CONF-006 重置**：重置为最后一次已保存值；恢复系统默认需独立二次确认。

## 10. 比例演化 `/ratio`

### 10.1 目标、阶段和数据源

- **页面目标**：查看六大类实际配置比例随时间的变化及与历史目标的偏差。
- **启用阶段**：Phase 3。
- **目标数据源**：历史快照接口；若 `GET /api/snapshot/history` 不含六类明细，需设计 ratios 专用接口，不能由前端 N+1 猜测。

### 10.2 页面模块与交互

- **RATIO-001 日期筛选**：范围、粒度和快照状态筛选。
- **RATIO-002 时间序列**：六类固定颜色；每个日期的 `R_category_in_six` 合计 100%；余额类不进入序列。
- **RATIO-003 目标线**：使用对应日期的目标历史；无历史记录时显示 N/A/默认标记，禁止用当前配置伪装历史。
- **RATIO-004 当前摘要**：当前六类实际、目标、偏差表。
- **RATIO-005 详情联动**：点击日期查看该快照金额、基金数和来源；不读取未定义的 `sub_detail`。
- **RATIO-006 图表形式**：时间序列折线/堆叠面积为主；若使用柱状图，必须支持多日期清晰对比和 100% 基线。

## 12. 跨页面状态联动

| 事件 | 必须刷新 | 不得修改 |
|---|---|---|
| 确认新快照 | 首页快照、余额、收益、最近操作、数据页快照列表 | 用户配置 |
| 设为当前快照 | 首页全部当前快照模块、月度默认值 | 历史数据 |
| 保存配置 | 首页目标/偏差、月度默认值、配置页 | 历史快照金额和历史目标记录 |
| 确认月度操作 | 最近操作、月度审计列表 | 当前资产快照金额 |
| AI 新消息 | 当前会话和会话列表顺序 | 资产/配置数据 |

一个辅助接口失败时只影响对应模块，禁止用单一全局 error 将整页已成功数据清空。
