## 实现策略

### 主路径 / Fallback 区分

**Bug 6（各类小计）** 关键设计：
```
用户操作 (改 dropdown / ✓确认 / 批量确认)
   ↓
derivedCategories useMemo 立即重算 (前端主路径)
   ↓
DataPage "各类小计" 表格立即更新 ✓
   ↓
await fetchLatest(1) (后端 fallback，用于首页跨页缓存)
```

不依赖入库操作 → 单独 ✓ 确认也能刷新。

### Bug 1 服务端 normalize 细节

fund_name 字符串差异 3 类：
1. 全/半角空格（`\u3000` vs ` `）→ replace
2. 连续空白 → `replaceAll("\\s+", " ")` 
3. 头尾空白 → trim

实现位置：
- `CategoryMapService.normalizeFundName(String)` 静态工具方法
- `match` 入参先 normalize，再用 mapper 查
- 新增 `FundCategoryMapMapper.selectByUserAndNormalizedNames`，SQL 用 `TRIM(REPLACE(REPLACE(fund_name, CHAR(12288), ' '), '  ', ' ')) IN (...)`
- 返回给前端的 `matchedFunds[].fundName` 用 **AI 解析的原始名**（保留 dropdown 显示），但 `category` 用 user_correct
