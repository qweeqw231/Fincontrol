## 一、背景

### 1.1 用户反馈（2026-07-25 上午）

> "在预览界面点击入库，并且预览界面无法自动退出。然后我点击取消，可以退出预览界面，current 被设置成入库日期。我再点击数据管理页面，比如传 7 月 24 号入库，解析成功，点击入库，报 ⚠ 入库失败: Request failed with status code 500。"

### 1.2 根因分析（5 层 bug）

| Bug | 位置 | 症状 |
|---|---|---|
| Bug-A | `DataPage.jsx:doConfirm` 成功路径 | 缺 `setShowConfirmModal(false)` 等 modal 衍生 state 清理，modal 不退 |
| Bug-B | `DataPage.jsx:doConfirm` 第 533-546 行末尾独立 try-catch | confirm 成功后**自动**调 setCurrent（"PR3+ BUG-004"），违反用户"确认后才改 current"的设计 |
| Bug-C | 用户视角 | "点取消 → current 被设"（实际是 confirm 已自动改了 current，× 只关 modal） |
| Bug-D | 后端 `SnapShotConfirmService.writeAssetRaw` 第 247 行 | 第二次 confirm 同 snapshot_date 用 `BaseMapper.insert` 撞 PK → 500 |
| Bug-E | 后端 `asset_snapshot` 表 unique key `uk_user_date_category` 是 3 列约束 `(user_id, snapshot_date, category)`，**不含** `is_latest`。`updateIsLatestBySnapshotDate` 翻旧行 `is_latest=false` 后行还在，新 INSERT 仍撞 unique key → 500（`Duplicate entry '1-2026-07-23-A股权类-0'`） |
| Bug-F（衍生） | `fund_category_map` 表 unique key `uk_user_fund` 是 2 列约束，同样 Bug-E 风险 |

### 1.3 设计收敛（与用户三轮迭代）

- 第 1 轮（用户原始诉求）：modal 不退 + current 被改 + 二次 500
- 第 2 轮（用户建议）：上传后自动改 current → 用户撤回（"万一没确认那 current 就不应该切"）
- **第 3 轮（最终）**：上传/parse 不改 current；confirm 成功后弹"设为当前吗?" modal，让用户主动选择

### 1.4 最终方案

> 数据写入 DB（confirm）和"设为当前显示日期"（setCurrent）**解耦**。
> 点"入库"蓝色按钮 → 写入数据 → preview 关 → 新 modal "设为当前吗?" 弹出：
> - 蓝色按钮"改为当前日期"（默认 autofocused）：调 setCurrent → 关 modal
> - 白色按钮"取消"：不动 current → 关 modal
> 主列表"设为当前"按钮保留为兜底。
> 后端：confirm 流程改为「先 DELETE 同 unique key 的旧行（事务内原子），再 INSERT/UPSERT 新行」，覆盖 asset_raw / asset_snapshot / fund_category_map 三张表。

## 二、实施范围

### 2.1 前端：改 DataPage.jsx（Fix 1 + Fix 2 + Fix 3）

#### Fix 1：doConfirm 真正清理 modal state

成功路径新增 10 个 setState（含 `setShowConfirmModal(false)` 真正关 modal）；失败 catch 块加防御 `setSetCurrentPrompt(null)`。

#### Fix 2：移除 doConfirm 末尾独立 try-catch 自动 setCurrent（行 533-546）

删除原"PR3+ BUG-004"逻辑 + 顶部 JSDoc 注释。

#### Fix 3：新增"设为当前吗?" prompt modal

- 新 state `setCurrentPrompt` / `setSetCurrentPrompt`
- 新辅助函数 `handleSetCurrentPromptConfirm`（先关 modal 再调 setCurrent）/ `handleSetCurrentPromptCancel`（只关 modal）

- 新 modal JSX（复用 `modal-confirm-backdrop` / `modal-confirm-card`），蓝色默认 + 白色取消

### 2.2 后端：改 SnapShotConfirmService（Fix 4 + Fix 5）

#### Fix 4（commit `5055015` 已推）：asset_raw 表幂等

- `AssetRawMapper` 加 `@Insert` 注解 SQL `upsertByFundName`（ON DUPLICATE KEY UPDATE）
- `SnapShotConfirmService.writeAssetRaw` 第 247 行改调 `upsertByFundName`

#### Fix 5（**本次 commit**）：asset_snapshot + fund_category_map 表幂等

- `AssetSnapshotMapper` 加 `@Delete` 注解 SQL `deleteByUserAndDateAndCategory`（新方法）
- `SnapShotConfirmService.writeAssetSnapshot` 头循环调 `deleteByUserAndDateAndCategory` 清扫 unique key
- `SnapShotConfirmService.writeFundCategoryMap` 头循环调 `fundCategoryMapMapper.deleteByUserAndFundName`（复用 1a.8.8 接口）
