**日期**：2026-07-25
**PR 名**：1b.4-pr7（pr7）
**目标**：修复 DataPage confirm modal 状态机连锁 bug（modal 不退 + 自动改 current + 二次入库 500）
**决策**：决策 33 v3（延伸）· DATA-016（DataPage UX 收尾）
**承接**：1b.4-pr6b（决策 33 v2）+ 1b.4-pr6b-recovery（V6 收尾）

## 一、背景

### 1.1 用户反馈（2026-07-25 上午）

> "在预览界面点击入库，并且预览界面无法自动退出。然后我点击取消，可以退出预览界面，current 被设置成入库日期。我再点击数据管理页面，比如传 7 月 24 号入库，解析成功，点击入库，报 ⚠ 入库失败: Request failed with status code 500。"

### 1.2 根因分析（4 层 bug）

| Bug | 位置 | 症状 |
|---|---|---|
| Bug-A | `DataPage.jsx:doConfirm` 成功路径 | 缺 `setShowConfirmModal(false)` 等 modal 衍生 state 清理，modal 不退 |
| Bug-B | `DataPage.jsx:doConfirm` 第 533-546 行末尾独立 try-catch | confirm 成功后**自动**调 setCurrent（"PR3+ BUG-004"），违反用户"确认后才改 current"的设计 |
| Bug-C | 用户视角 | "点取消 → current 被设"（实际是 confirm 已自动改了 current，× 只关 modal） |
| Bug-D | 后端 `SnapShotConfirmService` | 第二次 confirm 同 snapshot_date 触发唯一键冲突 → 500 |

### 1.3 设计收敛（与用户三轮迭代）

- 第 1 轮（用户原始诉求）：modal 不退 + current 被改 + 二次 500
- 第 2 轮（用户建议）：上传后自动改 current → 用户撤回（"万一没确认那 current 就不应该切"）
- **第 3 轮（最终）**：上传/parse 不改 current；confirm 成功后弹"设为当前吗?" modal，让用户主动选择

### 1.4 最终方案

> 数据写入 DB（confirm）和"设为当前显示日期"（setCurrent）**解耦**。
> 点"入库"蓝色按钮 → 写入数据 → preview 关 → 新 modal "设为当前吗?" 弹出：
> - 蓝色按钮"改为当前日期"（默认 autofocused）：调 setCurrent → 关 modal
> - 白色按钮"取消"：不动 current → 关 modal
> 主列表"设为当前"按钮保留为兜底。

#### Fix 2：移除 doConfirm 末尾独立 try-catch 自动 setCurrent（行 533-546）

- 新增注释说明："v3 设计：confirm 仅写数据，不改 current；改 current 由 Fix 3 prompt 让用户主动触发"

#### Fix 3：新增"设为当前吗?" prompt modal

新 state（紧跟 `confirmSuccess` 声明）：
```js
// Fix 3：入库成功后弹"设为当前吗?" prompt（蓝色默认改，white 取消不改）
const [setCurrentPrompt, setSetCurrentPrompt] = useState(null) // {date, fundCount} | null
```

新辅助函数（紧跟 `setCurrent` 函数定义后）：
```js
async function handleSetCurrentPromptConfirm() {
  if (!setCurrentPrompt) return
  const { date } = setCurrentPrompt
  setSetCurrentPrompt(null)  // 先关 modal，再调 API
  await setCurrent(date)    // 复用现有 setCurrent（含 fetchLatest + fetchMetaList）
}
function handleSetCurrentPromptCancel() {
  setSetCurrentPrompt(null)  // 不动 current
}
```

doConfirm 主 try 末尾（在 `setConfirmSuccess(true)` 之后）：
```js
setSetCurrentPrompt({ date: snapshotDate, fundCount: parseInfo?.fundCount ?? 0 })
```

新 modal JSX（放在预览 modal 之后、`batchToast` 之前，复用 `modal-confirm-backdrop` / `modal-confirm-card` 样式）：
```jsx
{setCurrentPrompt && (
  <div className="modal-confirm-backdrop" onClick={handleSetCurrentPromptCancel}>
    <div className="modal-confirm-card" onClick={(e) => e.stopPropagation()}>
      <div className="modal-confirm-title">✅ 已入库 {setCurrentPrompt.fundCount} 只基金</div>
      <div className="modal-confirm-sub">
        是否将 <strong>{setCurrentPrompt.date}</strong> 设为当前显示日期？
      </div>
      <div className="modal-confirm-actions">
        <button className="secondary-btn" onClick={handleSetCurrentPromptCancel}
          data-testid="set-current-prompt-cancel">取消</button>
        <button className="primary-btn" onClick={handleSetCurrentPromptConfirm} autoFocus
          data-testid="set-current-prompt-confirm">改为当前日期</button>
      </div>
    </div>
  </div>
)}
```
